## How to present the project accurately

Suggested portfolio wording:

> Guru is an independently assembled agricultural government-scheme RAG assistant, inspired by the problem statement and baseline feature outline of the referenced Agricultural Schemes RAG learning project. Guru adds a farmer-profile-aware conversational workflow, multilingual response selection, source/page evidence display, state/category document metadata, eligibility guidance and a FastAPI + Streamlit application structure. These capabilities should be described as completed only to the extent that they are implemented and tested in the submitted version.

Do not claim that the team invented RAG, FAISS, LangChain, agricultural scheme chatbots or the general concept of PDF question answering. Describe the team's own implementation, design decisions, integration, testing, evaluation and approved enhancements.

## Licence and reuse checklist

Before publishing or reusing any code/assets from the reference repository:

1. Open its `LICENSE` file and identify the licence and copyright holder.
2. If there is no licence, do not assume public visibility grants permission to copy or redistribute code; request permission or use an independently written implementation.
3. Preserve copyright and licence notices required by the applicable licence.
4. Attribute reused code, datasets, documents, images and other third-party assets separately.
5. Keep a `THIRD_PARTY_NOTICES.md` file if dependencies or assets require attribution notices.
